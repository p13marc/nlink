# Upgrading from 0.30.0 to 0.31.0

0.31.0 is the release that works through what nlink-lab found adopting
0.30.0 and then reviewing nlink from its side (#534). Most of it is bug
fixes. A bug fix needs no migration, but some of these change behaviour,
so read that section even if nothing fails to compile.

This guide grows with the cycle: each breaking change adds its section
when it lands.

## Compile breaks

### `ParsedExtAck` gained fields and is `#[non_exhaustive]` (#507)

`ParsedExtAck` now carries what the kernel's extended ack says beyond the
message and the offset:
- `missing_type` and `missing_nest`: the required attribute a request
  lacked. Generic netlink families report a missing attribute this way and
  with no message, so before this the error was a bare `EINVAL`.
- `policy`: the raw `NLMSGERR_ATTR_POLICY` nest.

`ParsedExtAck::describe()` renders all of it in one line. A struct literal
no longer compiles; build one with `ParsedExtAck::default()` and set fields,
or read the fields of the one `NlMsgError::ext_ack` returns.

```rust
// before
let ext = ParsedExtAck { message: Some(m), offset: None };
// after
let mut ext = ParsedExtAck::default();
ext.message = Some(m);
```

### `FqCodelConfig::ecn` is `Option<bool>` (#488)

The kernel turns fq_codel's ECN **on** by default, and a `false` was never
written, so ECN could not be turned off. The field is now
`Option<bool>`: `None` sends nothing and leaves the kernel's choice (on
for a new qdisc, unchanged on a replace). `.ecn(false)` turns it off. The
`.ecn(bool)` setter and `parse_params` (`ecn`/`noecn`) are unchanged.

```rust
// before
if cfg.ecn { /* … */ }
let cfg = FqCodelConfig { ecn: true, ..FqCodelConfig::new() };
// after
if cfg.ecn == Some(true) { /* … */ }
let cfg = FqCodelConfig::new().ecn(true);
```

### `DeclaredQdiscType::Prio` gains `priomap` (#487)

The variant is now `Prio { bands, priomap }` and `#[non_exhaustive]`.
Build it with `QdiscBuilder::prio().bands(n).priomap(map)`, and match it
as `DeclaredQdiscType::Prio { .. }`.

## Behaviour changes

- **Extended-ack TLVs are located by the header's flags (#507).**
  `NlMsgError::ext_ack(flags, payload)` and `to_error(flags, payload)` read
  `NLM_F_ACK_TLVS` and `NLM_F_CAPPED`. With `set_cap_ack(false)` the kernel
  echoes the whole request ahead of the TLVs, and the old fixed-offset
  reader parsed the request's own bytes as ext-ack. The payload-only
  `parsed_ext_ack`/`into_error` stay and still assume a capped error.
- **A kernel warning on a successful request is logged (#507)** as a
  `tracing` WARN from `nlink::netlink::message`. One example is
  `sch_htb: quantum of class 10002 is big. Consider r2q change.`, which
  `tc(8)` prints and nlink used to drop.
- **Error text names a missing attribute (#507).** A `Kernel` error's
  ext-ack text now includes `missing required attribute (type N)` and the
  policy's bounds when the kernel sends them.
- **nftables apply order (#460).** `NftablesDiff::apply` deletes sets,
  objects and chains *after* the rules that used them. A diff that drops a
  chain lists that chain's rules in `rules_to_delete`.
- **nftables keeps what an unmanaged rule uses (#459).** An undeclared
  chain, set, flowtable or object that a rule nlink does not manage still
  uses is no longer deleted. It is listed in the new
  `NftablesDiff::kept_in_use`. Anonymous sets never appear in a diff.
- **A refused nftables batch is `Error::NftBatch` (#481)**, not
  `Error::Kernel`. It lists every operation the kernel refused, each with
  its errno, ext-ack and the attribute it blamed. `errno()`, `ext_ack()`
  and every `is_*()` predicate answer for the first failure, so code that
  uses them is unchanged. Code that matched `Error::Kernel { .. }` on a
  `commit()`/`apply()` error needs an `Error::NftBatch { failures, .. }`
  arm.
- **`Error::Kernel`'s `message` no longer ends in `(os error N)` (#481).**
  The rendered error said the errno twice; it now says
  `Device or resource busy (errno 16)`.
- **pie and fq_pie always send `ecn`, `bytemode` (and fq_pie
  `dq_rate_estimator`) (#488),** as 0 when off. A replace that turns one
  off now turns it off.
- **`PrioConfig` with fewer than three bands fits the default priomap
  (#487)** instead of sending one the kernel refuses. A custom priomap that
  names a band past the last now fails before it is sent.
- **`replace_qdisc` looks at the slot first (#486).** A same-kind
  `htb`/`sfq`, a different fq_codel `flows`, and a kind change at the live
  qdisc's handle are all done by grafting a new qdisc over the live one;
  before, each was `EINVAL`. If the qdisc is the same kind and has
  classes, the replace is refused (`is_not_supported()`) rather than
  silently emptying it. Delete and re-add it if that is what you mean.
- **`add_qdisc` sends `NLM_F_EXCL` (#486).** An add over a live qdisc of the
  same kind, or at a handle in use, is now `EEXIST`; it used to change the
  live qdisc. Use `replace_qdisc` for "add or update".
- **`RateLimiter`'s ingress redirect is a matchall egress redirect at the
  recipe band (#458).** `reconcile()` replaces the u32 ingress redirect
  earlier releases installed, which dropped all ingress traffic. A
  limiter applied with 0.30 converges on the first `reconcile()`.
