# Upgrading from 0.31.0 to 0.32.0

0.32.0 carries the redesigns nlink-lab asked for in #534, which 0.31.0
left for their own cycle: namespace handles, the error model, ownership
and recreate in `NetworkConfig`, declarative traffic control, the
plan/apply split, and part of the nftables model. The rest of the
nftables redesign (`ChainKind`, `RuleSpec`, a typed `Change<T>` diff,
#708) moves to a later cycle.

Most compile breaks below are mechanical. Read the behaviour changes
too: several change what an existing program does without a compile
error.

## Compile breaks

### `Error::SequenceMismatch` and `Error::NamespaceRestoreFailed` are gone (#532)

Nothing constructed either variant: the sequence filter skips a stale
frame instead of failing, and namespace sockets have been made on a
thread of their own, which never needs restoring, since #185.
`Error::is_namespace_restore_failed()` goes with them. Remove any match
arm or call that names them; there is nothing to replace them with.

### `full` no longer includes `lab` (#532)

`lab` is test code: `LabNamespace`, `require_root!` and its siblings, and
a `tracing-subscriber` dependency. A crate that enabled `full` and used
any of those adds `lab`. Use it in `[dev-dependencies]` if only tests
need it:

```toml
[dev-dependencies]
nlink = { version = "0.32", features = ["lab"] }
```

### nlink no longer turns on tokio's `full` (#532)

The workspace asked tokio for `full`, so every crate depending on nlink
got it. nlink now asks for what it uses: `rt`, `net`, `sync`, `time` and
`macros`. A binary that relied on nlink for tokio features, such as
`rt-multi-thread` for `#[tokio::main]` or `signal`, names them in its own
tokio dependency.

### `LinkRecreate::blocked_by` is `Vec<Blocker>` (#513)

What would block a recreate was a list of strings; it is a list of
`config::Blocker`, an enum with one variant per kind of thing (`Address`,
`Route`, `Qdisc`, `Class`, `Filter`, `Fdb`, `Neighbour`, `ProxyNeighbour`,
`Nexthop`, `StackedLink`, `Port`, `ForeignNetnsPeer`, `Unsupported`). Each
one's `Display` is the string the list used to hold, so code that printed
them is unchanged:

```rust
// before
let text = recreate.blocked_by.join(", ");
// after
let text: Vec<String> = recreate.blocked_by.iter().map(ToString::to_string).collect();
if recreate.blocked_by.iter().any(|b| matches!(b, Blocker::Fdb { .. })) { /* … */ }
```

In JSON a blocker is an object tagged by `kind`:
`{"kind": "address", "dev": "v1", "address": "10.0.0.9", "prefix-len": 24}`.

### `ApplyResult` is `#[non_exhaustive]` and has `recreated` (#513)

It lists the links the apply deleted and created again, each a
`LinkRecreate` with its reason and its new `resets` (what the link lost:
an alias, a MAC address the kernel picked again). Build an `ApplyResult`
with `Default` and field assignment, not a struct literal.

### `RouteProtocol` has an `Other(u8)` variant (#512)

A protocol number nlink has no name for used to read back as `Unspec`, so
a route installed by `bird` with its own number, or by a config with
`NetworkConfig::route_protocol`, could not be told apart. `From<u8>` now
returns `RouteProtocol::Other(n)` for it. The enum has a variant with a
field, so `as u8` no longer compiles:

```rust
// before
let n = protocol as u8;
// after
let n = protocol.number(); // or u8::from(protocol)
```

`Display` prints a named protocol's name and an `Other`'s number, as
`ip route` does.

### `NetemConfig` is `#[non_exhaustive]` (#515)

It gained `ecn`, `slot`, `seed`, `distribution` and the three rate
overheads, and will gain more. A struct literal no longer compiles outside
nlink:

```rust
// before
let cfg = NetemConfig { delay: Some(d), ..Default::default() };
// after
let cfg = NetemConfig::new().delay(d);
```

Note that `new()` sets `limit` to 1000, tc(8)'s default, where
`..Default::default()` left it at 0.

### `FqPieOptions::ecn_prob_permille` is `ecn_prob_percent` (#631)

The kernel reports fq_pie's ECN probability as a whole percentage, and the
field always held that value. Its name said per-mille, and `ecn_prob()`
divided by 10, so the default of 10 % read as 1 %. Rename the field. Any
code that divided it by 10 itself should stop. `FqPieConfig::ecn_prob`
now refuses a fractional percentage.

### One `LinkStats` and one `LinkRates` (#525)

The crate had two of each. The `stats` module's are now the only ones:

- `nlink::netlink::stats::LinkStats` is the message-level `LinkStats`.
  Its counters are accessor methods, not fields. The link's name has
  moved to the snapshot:

  ```rust
  // before
  let bytes = snapshot.links[&ifindex].rx_bytes;
  let name = snapshot.links[&ifindex].name.clone();
  // after
  let bytes = snapshot.links[&ifindex].rx_bytes();
  let name = snapshot.names.get(&ifindex).cloned();
  ```

- `nlink::LinkRates` and `diagnostics::LinkRates` are now
  `stats::LinkRates`. Its fields are `f64` per second:

  | before | after |
  |---|---|
  | `rx_pps`, `tx_pps` | `rx_packets_per_sec`, `tx_packets_per_sec` |
  | `total_pps()` | `total_packets_per_sec()` |
  | `sample_duration_ms` | gone; the interval is between the two samples |
  | `rx_bps()` etc. as `u64` | `f64` |

  `stats::LinkRates` has no `name` field, and `between` no longer compares
  names. `StatsSnapshot::rates` and `RateSampler` do that comparison.
- `StatsSnapshot::rates(&previous, duration)` is now `rates(&previous)`.
  The interval is the time between the snapshots' `taken_at`.
  `StatsSnapshot` is `#[non_exhaustive]`; build one with `new()`, a
  `from_*` constructor, or `capture`.

### TC setters take typed units (#515)

Byte quantities take `Bytes`, and `PoliceAction` takes `Rate`:

```rust
// before
RedConfig::new().limit(100 * 1024).min(30 * 1024).max(90 * 1024);
BfifoConfig::new().limit(65536);
FqCodelConfig::new().memory_limit(32 << 20);
conn.plug_set_limit("eth0", parent, 10_000).await?;
PoliceAction::new().rate(1_250_000).burst(102_400);
PoliceAction::new().rate_bps(10_000_000);
// after
use nlink::{Bytes, Rate};
RedConfig::new().limit(Bytes::kib(100)).min(Bytes::kib(30)).max(Bytes::kib(90));
BfifoConfig::new().limit(Bytes::new(65536));
FqCodelConfig::new().memory_limit(Bytes::mib(32));
conn.plug_set_limit("eth0", parent, Bytes::new(10_000)).await?;
PoliceAction::new().rate(Rate::mbit(10)).burst(Bytes::kib(100));
PoliceAction::new().rate(Rate::mbit(10));
```

The setters affected are `GredConfig::limit`, `PlugConfig::limit`,
`PoliceAction::{peakrate, avrate, mtu}`, and those shown above.

Packet counts take `Packets` (#643), so a byte count cannot go where the
kernel counts packets, or the other way round:

```rust
// before
PfifoConfig::new().limit(1000);
FqCodelConfig::new().limit(10240);
FqConfig::new().limit(10_000).flow_limit(100);
NetemConfig::new().limit(5000).slot(NetemSlot::new(min, max).packets(5));
// after
use nlink::Packets;
PfifoConfig::new().limit(Packets::new(1000));
FqCodelConfig::new().limit(Packets::new(10240));
FqConfig::new().limit(Packets::new(10_000)).flow_limit(Packets::new(100));
NetemConfig::new().limit(Packets::new(5000)).slot(NetemSlot::new(min, max).packets(Packets::new(5)));
```

The setters are the `limit` of netem, fq_codel, codel, fq, sfq, choke, pie,
fq_pie, pfifo, skbprio, sfb and hhf, choke's `min` and `max`, fq's
`flow_limit`, HTB's `direct_qlen`, netem's slot `packets`, and the
declarative `QdiscBuilder::limit`. Their public fields are `Packets` (or
`Option<Packets>`) too; read one with `.as_u32()`. `From<u32>` converts. The
JSON shape is unchanged: a packet count is a number, and `"1000p"` reads as
well. The parsed views in `tc_options`, like their byte and rate fields,
stay raw integers. fq_codel's and fq_pie's `flows` count queues, not
packets, and stay `u32`.

### `QdiscConfig::default_handle` returns `Option<TcHandle>` (#515)

It returned `Option<u32>`, and no code read it. A `QdiscConfig` you
implement yourself that overrides it should return a `TcHandle`.

### Filter protocols and priorities are typed (#515)

The filter methods, the builders' `.protocol()`/`.priority()` and
`FilterConfig` take `EthProto` and `FilterPriority` instead of `u16`:

```rust
// before
conn.add_filter_full("eth0", parent, None, 0x0800, 100, filter).await?;
conn.del_filter("eth0", parent, 0x0003, 1).await?;
FlowerFilter::new().protocol(0x86DD).priority(10);
// after
use nlink::{EthProto, FilterPriority};
conn.add_filter_full("eth0", parent, None, EthProto::IP, FilterPriority::new(100), filter)
    .await?;
conn.del_filter("eth0", parent, EthProto::ALL, FilterPriority::new(1)).await?;
FlowerFilter::new().protocol(EthProto::IPV6).priority(FilterPriority::new(10));
```

What a dump reports is typed as well: `TcMessage::protocol()` returns an
`EthProto`, and `priority()` returns a `FilterPriority`. Both compare equal
to a `u16`. Use `.as_u16()` where a number is needed, and
`"ip".parse::<EthProto>()` for a name. `DEFAULT_FILTER_PROTOCOL` is an
`EthProto`.

### `DeclaredQdiscType` is `QdiscSpec`, which holds the configs (#515)

A declared qdisc now holds the imperative config. Read a field there,
and match on a tuple variant:

```rust
// before
if let DeclaredQdiscType::Netem { delay_us, loss_percent, .. } = q.qdisc_type() { /* … */ }
// after
if let QdiscSpec::Netem(netem) = q.qdisc_type() {
    let (delay, loss) = (netem.delay, netem.loss); // Option<Duration>, Percent
}
```

`QdiscBuilder` is unchanged, and `QdiscBuilder::spec(config)` takes a whole
config. `DeclaredQdiscType` is a deprecated alias of `QdiscSpec`.

**JSON/YAML.** Qdiscs are now written in human units, and the 0.31 field
names are still read:

| 0.31 | 0.32 |
|---|---|
| `"delay_us": 100000` | `"delay": "100ms"` |
| `"loss_percent": 1.5` | `"loss": "1.5%"` |
| `"rate_bps": 12500000` (bytes/s) | `"rate": "100mbit"` |
| `"burst_bytes": 32768` | `"burst": "32kib"` |
| `"target_us": 5000` | `"target": "5ms"` |
| `"perturb_secs": 10` | `"perturb": "10s"` |

These documents are now refused:
- one that sets a value both ways;
- one that misspells a field, which used to be ignored;
- one with a percentage outside 0–100;
- one with a rate without its unit.

A TBF without a limit now fails validation, and so fails `from_json_str`.

### One `ReconcileOptions` and one `ReconcileReport` (#532)

There were two unrelated types of each name. The recipes' types were at the
crate root; the nftables types were also borrowed by `NetworkConfig` and
`WireguardConfig`. Now there is one of each, in `nlink::reconcile`. Every
old path still names it.

```rust
use nlink::reconcile::{ReconcileOptions, ReconcileReport};

let opts = ReconcileOptions::new()     // 3 retries from 100 ms
    .with_max_retries(5)               // was `.max_retries(5)`
    .with_backoff(Duration::from_millis(50)) // was `.backoff(…)`
    .with_dry_run(true)                // now honoured by every layer
    .with_fallback_to_apply(true);     // a recipe's; the layers ignore it
let report = cfg.apply_reconcile(&conn, opts).await?;
let n = report.changes_made;           // was `change_count` in the layers
```

- The layers' report field `change_count` is now `changes_made`, the name
  the recipes used.
- A recipe's report now also carries `attempts`.
- The recipes retry `EBUSY`, `EAGAIN` and an interrupted dump, like the
  layers do. Each attempt dumps the tree again.

### `DiffOptions` is `PlanOptions`; `ApplyOptions` is a plan and an execution (#519)

```rust
// before
let diff = cfg.diff_with_options(&conn, DiffOptions::default().purge(true)).await?;
if opts.dry_run { /* … */ }
diff.apply(&conn, ApplyOptions::default()).await?;

// after
let diff = cfg.diff_with_options(&conn, PlanOptions::default().purge(true)).await?;
if opts.exec.dry_run { /* … */ }        // and opts.plan.purge, …
diff.apply(&conn, ExecOptions::default()).await?;
```

- `ApplyOptions` is `{ plan: PlanOptions, exec: ExecOptions }`.
  - Its `with_*` setters are unchanged.
  - Fields are read through `plan` (`purge`, `purge_tables`,
    `purge_address_devs`, `previous`, `recreate_policy`, `owned`) or
    `exec` (`dry_run`, `continue_on_error`, `verify`).
  - `diff_options()` is deprecated: read `plan`.
- `ConfigDiff::apply` takes `impl Into<ExecOptions>`, because a diff
  already holds its plan.
  - An `ApplyOptions` still converts.
  - `Default::default()` no longer infers; write `ExecOptions::default()`.
  - `verify` now works there too: the diff remembers its config and plan.
    Before, it was ignored, like the plan options are.
- `DiffOptions` is a deprecated alias of `PlanOptions`.

### `Stack` plans, then applies (#519)

`Stack::plan_in(ns, PlanOptions)` returns a `StackPlan`, and
`StackPlan::apply(ns, ExecOptions)` applies exactly that plan.
`Stack::apply*` are now plan + apply: one diff of every layer, where they
used to diff twice.

| 0.31 | 0.32 |
|---|---|
| `StackDiff` | `StackPlan` (deprecated alias) |
| `StackApplyReport` | `StackReport` (deprecated alias) |
| `stack.diff()`, `diff_in(ns)`, `diff_in_with(ns, o)`, … | `stack.plan(o)`, `plan_in(ns, o)` (the `diff*` methods are deprecated) |
| `report.nftables_change_count` | `report.nftables` |
| `report.dry_run: Option<StackDiff>` | `report.dry_run: bool`, and the plan in `report.planned` |
| `Stack { network, .. }` literal | `Stack::new().network(..)`; `Stack` is `#[non_exhaustive]` |

- `StackReport` also has `wireguard_devices_created` and `attempts`.
- `exec.verify` plans every layer again, and fails with the new
  `Error::StackNotConverged`. Its kind is `ErrorKind::NotConverged`.
- `Stack::apply_reconcile_in(ns, ReconcileOptions, ApplyOptions)` plans and
  applies again on a transient error, or on an nftables commit refused
  because the ruleset moved (`ERESTART`).
- `WireguardConfigDiff::apply(conn)` is new. `WireguardApplyResult` now
  serializes.

### `LinkChanges` is `#[non_exhaustive]` (#516)

It gained ten fields for the link attributes a config can now declare:
- `set_txqlen`, `set_alias`, `set_group`;
- the GSO/GRO limits;
- `set_promisc`, `set_protodown`;
- `add_altnames`/`del_altnames`.

Read it; don't build it.

### `DeclaredLinkType::Veth` has `peer_netns` and peer settings (#516, #680)

A veth's peer can be declared in another namespace
(`LinkBuilder::veth_peer_netns`), with its MAC, MTU and state there
(`veth_peer_address`, `veth_peer_mtu`, `veth_peer_up`/`veth_peer_down`):
the variant gains `peer_netns`, `peer_address`, `peer_mtu` and
`peer_state`. A pattern that names the variant's fields adds `..`:

```rust
DeclaredLinkType::Veth { peer, .. } => …
```

### File descriptors are `impl AsFd` (#532)

Every public parameter that took a file descriptor as `RawFd` or `i32`
takes `impl AsFd` now, so the compiler checks that it is open for as
long as it is used:

| Signature | Pass |
|---|---|
| `Connection::get_nsid(ns_fd)`, `set_nsid(ns_fd, nsid)` | `&File`, `&NamespaceFd`, `&Netns` |
| `Connection::set_link_netns_fd{,_by_index}(…, fd)` | the same |
| `Connection::new_in_namespace(ns_fd)`, `NetlinkSocket::new_in_namespace(protocol, ns_fd)` | the same |
| `Connection::<Nl80211>::set_wiphy_netns(wiphy, netns_fd)` | the same |
| `Connection::<Ovpn>::attach_socket{,_in_netns}(…, fd, …)` | `&UdpSocket`, `&TcpStream`, … |
| `VethLink::peer_netns_fd(fd)` | a namespace fd |
| `BpfFilter::new(fd)`, `BpfAction::from_fd(fd)` | the program fd your loader returned |
| `NetlinkSocket::send_with_fds(msg, fds)` | `&[BorrowedFd<'_>]` |

```rust
// before
conn.get_nsid(ns_file.as_raw_fd()).await?;
let filter = BpfFilter::new(prog_fd.as_raw_fd());

// after
conn.get_nsid(&ns_file).await?;
let filter = BpfFilter::new(&prog_fd);
```

The three builders, `VethLink`, `BpfFilter` and `BpfAction`, duplicate
the fd and hold the duplicate until the request is sent, so yours may be
closed right away. Before, they kept only the number, and closing your fd
first sent the kernel a closed or reused one. If the duplicate cannot be
made (the process is out of fds), creating the link or filter fails with
that error.

If all you have is a raw number, borrow it: `unsafe {
BorrowedFd::borrow_raw(fd) }`. The tc(8)-syntax parsers' `fd <n>` token
still takes a number, as tc(8) does.

`TunTap` and `NetlinkSocket` implement `AsFd` alongside `AsRawFd`.

### One way into a namespace: `Connection::new_in` (#532)

A connection in a namespace could be had seven ways:
- `namespace::connection_for{,_path,_pid}{,_async}`;
- `Connection::for_namespace`;
- `Connection::new_in_namespace{,_path}`;
- `NamespaceSpec::connection{,_async}`.

The facade had a `_in_namespace(&str)` and an `_in(NamespaceSpec)` form of
each function. There is now one entry point for each:

- `Connection::<P>::new_in(ns)`, and `new_in_async(ns)` for a GENL family;
- `facade::{apply, diff}::*_in(ns, …)`, `Stack::{plan_in, apply_in,
  apply_in_with, apply_reconcile_in, diff_in, diff_in_with}(ns, …)`,
  `StackPlan::apply(ns, …)`;
- `facade::watch::{route_changes_in, nftables_changes_in,
  wireguard_changes_in}(ns)` and `MultiNsWatch::add(key, ns)`;
- `ConnectionPool::new_in(ns, size)` and
  `ConnectionPoolBuilder::namespace(ns)`.

`ns` is anything `Into<NetnsTarget>`: an `ip netns` name (`&str`,
`String`), an open `&Netns` (or a `&LabNamespace`), a `NetnsRef`, a
`&Path`/`PathBuf`, a `NamespaceSpec`, or a `BorrowedFd`. Code that passed
a `NamespaceSpec` to the facade still compiles.

```rust
// before
let conn: Connection<Route> = namespace::connection_for("red")?;
let wg: Connection<Wireguard> = namespace::connection_for_async("red").await?;
let conn: Connection<Route> = namespace::connection_for_pid(pid)?;
let conn = Connection::<Route>::new_in_namespace_path("/proc/42/ns/net")?;
nlink::facade::apply::network_in_namespace("red", &cfg).await?;
let pool = ConnectionPool::<Route>::for_namespace("red", 4).await?;

// after
let conn = Connection::<Route>::new_in("red")?;
let wg = Connection::<Wireguard>::new_in_async("red").await?;
let conn = Connection::<Route>::new_in(NetnsRef::Pid(pid))?;
let conn = Connection::<Route>::new_in(Path::new("/proc/42/ns/net"))?;
nlink::facade::apply::network_in("red", &cfg).await?;
let pool = ConnectionPool::<Route>::new_in("red", 4).await?;
```

A `&str` is always a name. A path in one is refused, since a name cannot
contain `/`, so wrap a path in `Path::new`.

The old spellings are deprecated, not removed (see Deprecations). Two
things do break:
- **`Netns::connection` and `Netns::connection_async`**, added this cycle,
  are gone: use `Connection::new_in(&netns)`.
- **`ConnectionPoolBuilder::namespace`** takes `impl Into<NetnsTarget>`
  instead of `impl Into<String>`. A name still works, but a value whose
  only conversion was `Into<String>` does not. `ConnectionPool::namespace()`
  returns how the namespace was opened, for one opened by path or pid.

### `Error` is a struct; its variants are `ErrorDetail` (#526)

`nlink::Error` was an enum of about thirty variants. It is now a struct,
one pointer wide, that carries:

- **`kind()`**: unchanged, and still the way to recover;
- **`detail()`**: an `&ErrorDetail`, the enum of the old variants;
- **`context()`**: what was being done, outermost first.

`KernelWithContext` is gone. Every kernel error is `ErrorDetail::Kernel`,
and its operation is in `context()`.

**Matching.** Prefer `kind()` or an `is_*` predicate. Where you need a
detail, match `detail()`:

```rust
// before
match err {
    Error::Kernel { errno, .. } | Error::KernelWithContext { errno, .. } => …,
    Error::QdiscNotFound { .. } => …,
    _ => …,
}

// after
match err.detail() {
    ErrorDetail::Kernel { errno, .. } => …,
    ErrorDetail::NotFound { object: ErrorObject::Qdisc { .. } } => …,
    _ => …,
}
```

**One not-found detail (#718).** `InterfaceNotFound`, `NamespaceNotFound`,
`QdiscNotFound` and `FamilyNotFound` are one detail, `NotFound { object }`,
whose `ErrorObject` says what was missing: `Link`, `Namespace`, `Qdisc` or
`GenlFamily`. An `IfError::NotFound` converts to it too. The messages read as
they did, and `is_not_found()` is unchanged; `Error::object()` returns the
object. The constructors stay: `Error::interface_not_found(name)`,
`namespace_not_found`, `qdisc_not_found` and `family_not_found`, and
`Error::not_found(object)` makes any other.

| Before | After |
|---|---|
| `ErrorDetail::InterfaceNotFound { name }` | `ErrorDetail::NotFound { object: ErrorObject::Link { name } }` |
| `ErrorDetail::NamespaceNotFound { name }` | `ErrorDetail::NotFound { object: ErrorObject::Namespace { name } }` |
| `ErrorDetail::QdiscNotFound { kind, interface }` | `ErrorDetail::NotFound { object: ErrorObject::Qdisc { dev, kind: Some(kind), .. } }` |
| `ErrorDetail::FamilyNotFound { name }` | `ErrorDetail::NotFound { object: ErrorObject::GenlFamily { name } }` |

`ErrorDetail::Kernel` no longer stores `message`, the `strerror` text of its
errno: `Display` computes it.

**Constructing.** Use the helpers, or convert a detail:

| Before | After |
|---|---|
| `Error::InvalidMessage(s)` | `Error::invalid_message(s)` |
| `Error::InvalidAttribute(s)`, `Error::NotSupported(s)` | `Error::invalid_attribute(s)`, `Error::not_supported(s)` |
| `Error::Io(e)`, `.map_err(Error::Io)` | `Error::from(e)`, `.map_err(Error::from)` |
| `Error::Validation(v)` | `Error::validation(v)` |
| `Error::Timeout`, `DumpInterrupted`, `PoolClosed` | `Error::timeout()`, `dump_interrupted()`, `pool_closed()` |
| `Error::Truncated { expected, actual }` | `Error::truncated(expected, actual)` |
| `Error::KernelWithContext { .. }` | `Error::from_errno_with_context_ext_ack(..)` |
| any other `Error::X { .. }` | `Error::from(ErrorDetail::X { .. })` |

**A context is kept on every error.** `with_context` and
`ResultExt::context` used to keep a context only on a kernel error. On an
I/O error, a refused nftables batch, a validation failure or a parse they
returned the error unchanged. Each now keeps its context, and `Display`
shows it in front: `delete namespace red: I/O error: …`. A kernel error
reads as before: `kernel error: File exists (errno 17)` alone, and
`add_link(d0): File exists (errno 17)` under a context.

Code generated by `nlink-macros` 0.32 constructs errors through the
helpers. An older `nlink-macros` generates `Error::InvalidMessage(…)` and
does not compile against nlink 0.32. Take the macros through nlink's
re-export (`nlink::macros`), which keeps the two versions matched.

### `TcpInfo` has more fields (#166)

`TcpInfo` reads what kernels appended to `tcp_info` after `snd_wnd`, AccECN's
counters included. A struct literal naming every field needs the new ones;
one ending in `..TcpInfo::default()` compiles as it is.

### `SecurityAssociation` is `#[non_exhaustive]` (#166)

It gained `pcpu`, the CPU of a per-CPU SA (`XFRMA_SA_PCPU`), and is
`#[non_exhaustive]` now, so the next field is not a break. It is what
`get_sa`, `dump_sas` and the XFRM events return; code that built one with a
struct literal (a test double, say) cannot any more. Match it with `..`.

### `sys_sizeof`'s attribute tables are gone (#167)

`nlink::netlink::sys_sizeof` carried hand-copied tables of kernel
attribute ids and message types: `xfrm_msg_type`, `xfrm_attr`,
`nft_ct_keys`, `tca_htb_attr`, `tca_flower_key`, `ifla_attr`, `rta_attr`,
`ctnetlink_attr`, `dpll_a`, `devlink_attr` and `ethtool_a`. They were a
test fixture that happened to be public. Most were partial, and #265 found
`TCA_HTB_OFFLOAD` wrong in one of them and in the constant it was meant to
check. The UAPI audit now checks nlink's own constants against the kernel
headers and YNL specs directly, so the copies are removed.

If you used one, take the value from its typed home instead: an enum
discriminant (`DpllAttr::Id as u16`, `CtKey::Mark as u32`), a
`types::*` constant (`types::tc::qdisc::htb::TCA_HTB_RATE64`), or
`libc` / your own constant for the rest. `sys_sizeof::{xfrm,
nft_verdict, nf_hook}` and `DEVLINK_MCGRP_CONFIG_NAME` stay.

### `HealthReporter` has `port` (#777)

`devlink::HealthReporter` gained `port: Option<u32>`, the port a reporter
belongs to (`None` for the device's own). Code that builds one with a struct
literal adds the field. `get_health_reporter(bus, dev, name)` returns the
device's own reporter of that name. A port's is in `get_health_reporters`,
where it used to come first and pass for the device's.

### Multipath weights are `u16` (#783)

A multipath next hop's weight is a `u16`, 1 to 256:
- `ParsedNextHop::weight` (now `#[non_exhaustive]`, with `encap_type` and
  `flow`);
- `RouteNexthop::weight`;
- `NextHop::weight` and `RouteNexthopBuilder::weight`.

As a `u8`, 256 could not be said and read back as 255. A `u8` variable
passed to a setter needs `.into()`.

### `SfqConfig`, `FqCodelConfig` and `TbfConfig` have more fields (#806)

- `SfqConfig` gained `divisor`, `flows`, `depth` and `headdrop`.
- `FqCodelConfig` gained `drop_batch` and `ce_threshold_selector`. Its parsed
  counterpart, `FqCodelOptions`, gained `ce_threshold_selector`.
- `TbfConfig` gained `overhead`, `mpu` and `linklayer`.

Code that builds one with a struct literal adds the fields, or ends it with
`..Default::default()`. The fluent setters are unchanged. `sfq::TcSfqQoptV1`
gained its trailing `stats`.

### `RedConfig` and `ChokeConfig` have a `probability`, not `max_p` (#819)

Both could not be installed (the kernel wants a table nlink did not send).
They now carry what tc(8) derives the table from:

- `max_p: u8`, a 0–255 scale, is `probability: f64`, a fraction from 0.0 to
  1.0 (0.02 by default). `max_probability(percent)` still takes a
  percentage.
- Both gained `avpkt`, `burst` and `bandwidth`, and setters for them.
- `RedConfig` gained `nodrop`.

### More qdisc fields (#820, #821)

- `GredConfig` gained `ecn` and `harddrop`.
- `PieConfig` gained `dq_rate_estimator`.
- `FqConfig` gained `buckets`, `horizon`, `horizon_drop` and `timer_slack`.

Code that builds one of these with a struct literal adds the fields, or ends
it with `..Default::default()`.

### `ematch::TcfEmU32` has `offmask` (#828)

The wire struct is the kernel's whole `struct tc_u32_key` now, 16 bytes; a
struct literal adds `offmask: 0`. `EmatchU32`'s `mask` and `value` are the
32-bit word at `offset` in host order, which the writer sends big-endian.
Before, a u32 ematch never installed, so no tree depended on the old order.

### `ethtool::LinkState::link` is `Option<bool>` (#839)

A driver without `ethtool_ops::get_link`, such as a dummy, gets no
`ETHTOOL_A_LINKSTATE_LINK`. `link` used to be `false` then, which reads as
"no carrier"; it is `None`. Match on `Some(true)`/`Some(false)`, or use
`link == Some(true)` where `false` and unknown mean the same to you. And
`Features::is_changeable` now also requires the feature in `hw`, as
ethtool's `[fixed]` does: code that tried to change a feature it called
changeable, and failed, sees it fixed now.

## Deprecations

- **`MirredAction::{redirect_by_index, mirror_by_index,
  ingress_redirect_by_index, ingress_mirror_by_index}`** are replaced by
  `redirect_to_egress`, `mirror_to_egress`, `redirect_to_ingress` and
  `mirror_to_ingress` (#515). To redirect to an IFB, use
  `redirect_to_egress`.
- **`Connection::new_in_namespace_fd` and
  `NetlinkSocket::new_in_namespace_fd`** (#532): `new_in_namespace` takes
  `impl AsFd` itself now.
- **The namespace spellings** (#532), replaced by
  `Connection::new_in`/`new_in_async` and the facade's `*_in`:
  - `namespace::connection_for`, `connection_for_path`, `connection_for_pid`
    and their `_async` forms;
  - `Connection::for_namespace`, `new_in_namespace`, `new_in_namespace_path`
    and `new_in_namespace_fd`;
  - `NamespaceSpec::connection` and `connection_async`;
  - `facade::{apply, diff}::{network, nftables, wireguard}_in_namespace`;
  - `facade::watch::{route, nftables, wireguard}_changes_in_namespace`;
  - `Stack::apply_in_namespace`;
  - `ConnectionPool::for_namespace`.

  `NetlinkSocket::new_in_namespace{,_path}`, the socket-level
  constructors, stay.
- **`Connection::get_timeout()` → `operation_timeout()`** (#532), the name
  without the `get_` prefix the rest of the API does not use.
- **`namespace_events` (`NamespaceEventSubscriber`,
  `NamespaceNetlinkEvent`)** (#532). It duplicates `NetworkEvent::NewNsId`
  and `NetworkEvent::DelNsId`:

  ```rust
  // before
  let mut sub = NamespaceEventSubscriber::new().await?;
  while let Some(ev) = sub.recv().await? { /* NamespaceNetlinkEvent */ }

  // after
  let conn = Connection::<Route>::new()?;
  conn.subscribe(&[RtnetlinkGroup::NsId])?;
  let mut events = conn.events().await;
  while let Some(ev) = events.next().await {
      if let NetworkEvent::NewNsId(m) = ev? { /* m.nsid(), m.pid() */ }
  }
  ```
- **`Connection::stream_classes()` and `stream_filters()`** (#778). They
  always returned an empty stream: a class or filter dump answers for one
  interface, and they sent none. Stream one interface's with
  `stream_classes_by_index(ifindex)` and
  `stream_filters_by_index(ifindex, parent)`, or read every interface's
  with `get_classes()`/`get_filters()`.

## Behaviour changes

- **An error from a namespace connection names it (#718).** A connection
  made in a namespace (`Connection::new_in`, `Netns::connection`,
  `sibling`) puts the namespace's label at the end of its errors'
  `Display`: `… (errno 101) [netns red]`. Code that compared a whole
  message, or matched its end, must allow the suffix; `Error::netns()`
  reads the label, and `kind()`, `errno()` and the predicates are
  unchanged. Errors from a connection in the caller's own namespace read
  as before.
- **A mirred `dev` is resolved when the filter is installed (#645).**
  `MirredAction::parse_params(&["…", "dev", "ifb0"])` used to look the name
  up in `/sys/class/net` as it parsed, in the calling process's namespace,
  which is the wrong one for a connection in another. It keeps the name now
  (`MirredAction::to_dev`). The connection that installs the filter or
  action (`add_filter*`, `replace_filter*`, `change_filter*`, `add_action`,
  a declared tree's apply) resolves it in its own namespace, and a name it
  doesn't have is `is_not_found()` there rather than at the parse. Writing
  such an action's options without a connection, by calling
  `write_options` directly, is an error until `resolve_devices` gives it
  the ifindex.
- **`RouteFilter::from_if(name)` installs (#645).** The name is resolved
  the same way. It used to fail every install with "must be resolved to
  index before use".
- **A config's JSON has its TC trees (#645).** `NetworkConfig` writes a `tc`
  key when it declares trees, and `ConfigDiff` writes `tc` when one differs;
  both used to leave trees out, so a document read back lost them. A plan's
  `tc-tree` step carries its `tree` and `previous`, and reads back.
- **`is_goto_chain(-1)` is false (#645)**, and goto chains keep 28 bits.
  Code that used the predicate to tell a goto from `continue` got the
  wrong answer for `continue`.
- **ife refuses `use tcindex` past 65535 (#645)**, which it truncated.
- **`conform-exceed` is exceed first (#751).** `PoliceAction::parse_params`
  and `nlink-tc` read `conform-exceed A/B` as tc-police(8) does: A is the
  action for what exceeds the rate, B for what conforms. They read it the
  other way round. A pair written for nlink's old order now polices the
  other traffic; swap its halves, or write `conform A exceed B`, which means
  the same in both.
- **A police from tc(8)'s words is tc's (#800).**
  `PoliceAction::parse_params`, `nlink-tc` and a tree document's police
  fill in what a line leaves out as tc-police(8) does. What exceeds the rate
  is reclassified, where it was dropped. The mtu is left to the kernel
  (`255 << cell_log` with a rate, no limit without one), where it was 2047.
  Add `conform-exceed drop` and `mtu 2047` to a line written for the old
  defaults to keep its meaning. `PoliceAction::new()`'s defaults are
  unchanged.
- **Action lines read as tc(8) reads them (#817).** Two readings changed.
  An skbedit `priority` is a class id, in hex, so `priority 10` sets 0x10
  where it set 10, and `priority 1:10` is 0x10010 where it was an error;
  write `priority 0:a` for decimal 10. And a pedit line without a verdict
  is `pass`, as tc-pedit(8) makes it, where it was `pipe`; add `pipe` to
  keep the old meaning. `PeditAction::new()`'s default is unchanged.
  skbedit's and ct's `to_params` write a masked mark as `mark V/M`, the
  form tc reads, where they wrote `mark V mask M` and `mark V M`. Both
  forms still parse.
- **u32 values read as tc(8) reads them (#831).** A raw match's value
  (`match u16 80 0xffff at 22`) is decimal unless it has a `0x` prefix,
  where it was always hex: a line written for the old reading changes
  meaning, so write `0x50` for 80 in hex, or `80`. `match mark` reads both
  numbers the same way. Keys at one offset merge, as tc's do, so a dump of
  a filter with `ip sport` and `ip dport` shows one key; two matches that
  disagree on the same bits are refused where both were sent.
- **qfq's `to_params` writes `maxpkt` (#826)**, tc's word, as a plain byte
  count; `lmax` still parses.
- **Qdisc lines read as tc(8) reads them (#819, #820).**
  - A red or choke `probability` is a fraction, so `probability 2` is
    refused and `0.02` is 2%; it was read as a percentage.
  - choke's `limit`, `min` and `max` are packet counts, as tc reads them,
    and no longer take a size suffix (`100k`).
  - sfb's `increment` and `decrement` are probabilities from 0.0 to 1.0,
    where they were the raw 0–65535 value; `SfbConfig::increment()` still
    takes the raw value. A bare `rehash` or `db` is milliseconds, where it
    was microseconds.
  - An `SfbConfig` field left unset is sent as tc's default, where it was
    sent as 0.
  - cake's `raw` also sets the overhead to 0 and the ATM mode to none.
- **Address matches in bridge and netdev tables start matching (#708).**
  Their guard was `meta nfproto`, which in those tables is the table's own
  family, so they matched nothing; it is `meta protocol` now. The next
  apply replaces such rules, and traffic they were written for starts
  hitting them. Rules in other tables lose only redundant guards, which
  the diff ignores: they are not replaced.
- **`Chain::device` adds a device (#703).** Called twice, it bound the
  chain to the second device only; now the chain is bound to both (`devices
  = { a, b }`), as `Flowtable::device` always did. The declarative
  `DeclaredChainBuilder::device` does the same; `DeclaredChain::device()`
  is `None` for a chain on several devices (read `devices()`), and a
  declared chain's JSON has `devices`, a list, where it had `device`.
- **A bare gate time is nanoseconds (#751)**, as tc-gate(8) reads it. It
  was microseconds; a value written for that is now a thousand times
  shorter. Write the unit (`1ms`, `100us`) to mean the same in both.
- **An enum value nlink doesn't know reads as absent (#727).** A message
  decoded by `#[derive(GenlMessage)]` or `#[derive(NetlinkAttrs)]` (dpll,
  ovpn, net_shaper, and your own families) used to fail with
  `InvalidMessage` when an enum field carried a value its `GenlEnum` had
  no variant for. An `Option<E>` field is now `None` and a `Vec<E>` field
  skips the element, as for an attribute the derive doesn't know. Code
  that relied on the error to detect a newer kernel can't any more; a
  `None` where the attribute should be present is the sign now.
- **`is_not_found()` knows a delete's "not there" (#526).** The kernel
  answers a route delete that matches nothing with `ESRCH`, and an address
  delete with `EADDRNOTAVAIL`. `del_route` and `del_address` errors with
  those errnos now answer `is_not_found()` and `kind() == NotFound`; they
  answered neither. The same errnos from any other request are unchanged.
  `Error::request_type()` gives the refused request's `nlmsg_type`.
- **A failed apply step names itself (#526).** A `NetworkConfig` apply
  that stops on an error used to return the kernel's answer bare:
  `replace_route: Network is unreachable (errno 101): …`, which named no
  route. The error now carries the step's operation as its outermost
  context: `add route 10.9.0.0/24: replace_route: Network is unreachable
  …`. It also carries the step's object in `Error::object()`, here
  `ErrorObject::Route`. Code that matched the message from its start
  must allow the prefix. `kind()`, `errno()` and the predicates are
  unchanged. A WireGuard apply names the device or peer it failed on in
  the same way.
- **`ApplyError` serializes more (#526).** Beside `operation` and `error`
  (still the message) it has `kind`, `errno`, `ext-ack`, `context` and
  `object`. A consumer that read only the two old fields is unaffected.
- **Nexthop group weights are the real weights (#672).** The wire
  carries a member's weight minus one, and nlink passed it through both
  ways. `NexthopGroupBuilder::member(id, 3)` now makes a member of weight
  3; it used to make one of weight 4. `NexthopGroupMember::weight()`
  returns 3 for it, where it used to return 2. Code that compensated, by
  passing `w - 1` or adding one to what it read, drops that. Both take and
  return a `u16` now.

- **A static FDB entry is no longer dynamic (#663).** `FdbEntry::is_dynamic()`
  is false for a `NUD_NOARP` entry, which `is_static()` now reports, and
  `flush_fdb` keeps it. Code that used `is_dynamic()` to find static
  entries should use `is_static()`. And `FdbEntryBuilder::permanent()`
  was always a local entry on a bridge; for one that forwards to its
  port, use `static_()`.

- **MACsec SCIs are big-endian, MAC then port (#516).** The value
  `MacsecDevice::sci` and `MacsecRxSc::sci` report, and the one
  `add_rx_sc`/`add_rx_sa` take, used to be byte-reversed against the
  kernel's and `ip macsec show`'s. Code that stored nlink's old values
  should reverse their bytes (`u64::swap_bytes`), or read them again.

- **A route that replaces one prints as `~ route … (replacing …)`
  (#518)**, not `+ route`. `routes_to_add` still holds it.
- **An IPv6 address moved to another prefix is removed at the old one
  right before it is added (#461), and the summary now says so in that
  order.** A failure of that removal follows `continue_on_error` like any
  other step. It used to fail the apply regardless.

- **A classful qdisc added at the root without a handle sits at `1:`
  (#515)**, instead of the kernel's `8001:`. This covers htb, prio, hfsc,
  drr, qfq, ets, multiq, mq, mqprio, taprio, atm and dsmark. Code that
  then named `8001:` should name `1:`, or pass the handle it wants.
- **`PerHostLimiter::remove` and `PerPeerImpairer::clear` leave a root
  they didn't build (#515).** A user's qdisc, or the other recipe's tree,
  is no longer deleted. `PerHostLimiter::remove` returns errors it used
  to swallow.

- **`NetworkConfig::validate()` refuses more (#518)**, and a diff runs it
  first. Before, each of these failed mid-apply, after the links before
  it were created, or never converged:
  - a kind setter called on another kind;
  - a VNI past 24 bits;
  - an IPv4 route with host bits;
  - table 0;
  - a cycle of masters;
  - a VLAN declared up on a lower device declared down;
  - a MAC on an ovpn or L3 netkit link.

  A missing parent or master is reported in `ConfigDiff::links_missing`,
  and the apply refuses it.
- **A second context stacks (#526).** `with_context` on a kernel error
  that has one already reads `"outer: inner"` in its `Display`; the outer
  one used to be dropped.
- **The diffs' `Display` has no trailing newline (#532).**
  `WireguardConfigDiff`'s had one; `ConfigDiff`'s and `NftablesDiff`'s
  did not. Print them with `println!`.
- **A declared prio qdisc sits at `1:` (#514)**, as HTB already did, so
  its classes and filters can name it. One the kernel had put at an
  automatic handle (`8001:`) is replaced once, on the first apply after
  the upgrade. Declare `.handle(..)` to keep another.
- **Netem percentages are rounded, as tc rounds them (#633).** nlink now
  puts the same probability in the kernel as tc(8): 1 % is 42949673, not
  42949672. A netem installed by an older nlink is one unit off, so a
  `PerPeerImpairer` or `NetworkConfig` reconcile replaces it once, on the
  first run after the upgrade. Some values, 1.2 % among them, used to be
  replaced on every run, and now converge.
- **fq_pie's `ecn_prob` is sent as a percentage (#631).** A config that
  asked for 20 % used to install 200 %, and now installs 20 %.
- **cake sends what tc sends (#635).**
  - `CakeConfig::new()` has `split_gso` on, the kernel's default. It was
    off, and was never sent, so it made no difference. `.split_gso(false)`
    and `no-split-gso` now turn splitting off.
  - The `nat`, `wash`, `ingress` and autorate flags are sent off as well
    as on, so a replace turns off one that was on.
  - An `rtt` with no `target` brings a target of a twentieth of the RTT,
    as tc's `rtt` does.
- **`SfqConfig::new()` leaves sfq's limit to the kernel (#637).** The
  `limit` field defaults to 0 instead of 127. The kernel's limit is still
  127, but a default sfq now has 128 flows rather than 127, the same as
  tc's. Code that read `cfg.limit` expecting 127 gets 0.
- **`StatsTracker` measures between snapshots, not calls (#525).** A
  rate is over the time between the two snapshots' `taken_at`.
  `DiagnosticReport::timestamp` is when the link counters were read, the
  end of the link dump, not the start of the scan.
- **An undeclared sfq `perturb` is the kernel's 0 (#515).** It is
  compared like any field. A declared sfq on a device whose sfq perturbs
  is replaced once, unless the declaration sets the period.
- **MSRV is 1.88** (#532). It was 1.98, the fleet toolchain the project
  builds with, which still builds it.
- **Rule statements decode typed (#528).** `RuleInfo::expressions()`
  returns `RuleExpr::Limit`, `Log`, `Reject`, `Masq`, `Nat`, `Redir` and
  `FlowOffload` where it returned `RuleExpr::Unknown { name: "limit" | "log"
  | …, data }`. Code that matched `Unknown` by name, to read the raw
  attributes, matches the typed variant instead. A shape these variants
  cannot carry still comes back as `Unknown`: a byte-rate limit, or a log
  with a level or flags.
- **A byte-rate limit object reads back as a limit (#528).**
  `ObjectState::Limit` holds it now, with `LimitExpr::kind ==
  LimitKind::Bytes`, where it used to be `ObjectState::Other`. A
  `RuleExpr::Limit` can be a byte limit too, so code that reads
  `LimitExpr::rate` as packets should check `kind`.
- **A rule's key is no longer in its comment (#527).** nlink keeps a
  declared rule's key in its own userdata TLV (type `0xF0`). `nft list`
  used to show the key as `comment "nlink:<key> …"`; it no longer shows it,
  and `RuleInfo::comment_text` is the user's comment alone. The key and
  the comment each get libnftnl's 127 bytes, where they used to share them.
  Rules an older nlink wrote are still read by their `nlink:` comment, so
  upgrading does not re-add or replace them. Code that parsed `nlink:`
  out of `comment_text` should read `RuleInfo::key`.
