# Upgrading from 0.25.0 to 0.26.0

0.26.0 is a **bug-fix release**, like 0.25.0 before it, and it is a bigger one.

The theme, stated plainly because it explains everything below: almost none of
these were logic errors in isolation. They were **places where nothing was
checking**. Wrong constants because the audit gate only read `#[repr]` enums.
Wrong byte order because the gate only banned the reader half. Three separate
HTB default-class bugs because no test ever asserted that traffic was
classified. Failed dumps reported as success because the recv loop was
copy-pasted nine times and the copies disagreed.

And the reason they accumulated for a whole cycle: `has_module()` checked
`/sys/module/<name>` alone, so the integration tests that would have caught them
**skipped** — and a skipped test reports `ok`. That one is fixed too, and it is
why the list is this long.

Most upgrades need no code changes. But more of these change what your existing
code *does* than in 0.25.0, and several do it with no compiler error. **Read
section 1 even if you read nothing else** — if you use `RateLimiter`,
`PerHostLimiter` or `PerPeerImpairer`, your traffic was not being shaped.

---

## ⚠️ Silent behaviour changes — read these

### 1. TC shaping did not shape. At all.

**Affects:** `RateLimiter`, `PerHostLimiter`, `PerPeerImpairer` — anything built
on them, including the `bidirectional-rate-limit` and `per-peer-impairment`
recipes.

Three independent bugs put the HTB `default` class at a handle no class existed
at. When `htb_classify` cannot resolve `defcls` it returns `HTB_DIRECT`: the
packet leaves the interface **completely unshaped**, with no error, no log, and
no dropped counter to notice.

| | what it did |
|---|---|
| `RateLimiter` | wrote `default_class(0x10)` — 16 — while creating the class at `1:10`, decimal 10. It installs no filters, so that class was the only thing between traffic and the wire. **Every packet bypassed the shaper.** |
| `PerHostLimiter::apply` | pointed `default` at `n+1`, the *last rule's* class. Unmatched traffic was shaped at the last rule's rate instead of `default_rate`; with no rules it named the inner class `1:1` and fell through to `HTB_DIRECT`. |
| `PerHostLimiter::reconcile` | used `n+2` — so the two verbs built different trees and apply-then-reconcile was never a no-op. |

**What to do:** nothing in your code. But if you tuned rates against observed
throughput, you were tuning against an unshaped link — re-measure. A limiter
that "seemed not to do much" was not doing anything.

The default class is now pinned at `1:ffff` (leaf `ffff:`), independent of the
rule count, so there is nothing left to derive and the two verbs cannot
disagree. **If you read class handles back** — a dashboard scraping
`tc -s class show`, an alert keyed on `1:3` — the default class moved.

### 2. `PerHostLimiter::limit_port` matched *everything*

**Affects:** `limit_port`, `limit_port_range`, and any hand-built
`FlowerFilter` carrying only L4 keys.

`cls_flower` reads `ip_proto` and the port keys only inside

```c
if (key->basic.n_proto == htons(ETH_P_IP) || key->basic.n_proto == htons(ETH_P_IPV6))
```

and `n_proto` comes from `TCA_FLOWER_KEY_ETH_TYPE` — **not** from the filter's
`tcm_info` protocol. nlink's address setters imply the ethertype; the L4 ones
did not. So the kernel ACKed the request and installed a **match-all**
classifier: a rule meant for port 443 sent *all* IPv4 traffic on the interface
to that rule's class.

`FlowerFilter::write_options` now returns an error rather than emitting a key
the kernel will discard:

```rust
// 0.25: installed silently, matched everything
FlowerFilter::new().classid(cid).ip_proto_tcp().dst_port(443)

// 0.26: say which ethertype
FlowerFilter::new().classid(cid).ipv4().ip_proto_tcp().dst_port(443)
```

An address setter still implies it, so `.dst_ipv4(..).dst_port(443)` is
unchanged.

### 3. A failed dump returned `Ok` with a short list

**Affects:** every dump — most sharply `sockdiag`, and every `diff()` built on
one.

`NLMSG_DONE` carries the dump's result code as an `int` payload, and nothing
read it:

```text
SOCK_DIAG_BY_FAMILY, sdiag_protocol = DCCP
  -> NLMSG_DONE, payload i32 = -2   (-ENOENT)
```

Not `NLMSG_ERROR` — `NLMSG_DONE`. `sockdiag.rs` answered
`NLMSG_DONE => return Ok(sockets)`, so a query the kernel **refused** came back
as "no sockets found".

Any dumper that failed partway yielded a partial list indistinguishable from a
complete one. That is worst on the declarative paths, where `diff()` builds a
plan from a dump: objects that exist become invisible and the diff proposes
creating them — and with purge enabled, proposes deleting what it never saw.

**What to do:** calls that returned `Ok` with a truncated list now return
`Err`. If you have a `match` on a dump result that treated an empty vec as
"nothing there", it will now see the kernel's error instead. That is the point,
but it is a new error path.

### 4. `NLM_F_DUMP_INTR` is now checked everywhere

**Affects:** `dump_stream`, the `*_with_resync` wrappers, the `Store`
watch-cache, and every nftables dump.

A torn snapshot — the dump iterator's data structure mutated mid-dump — was
checked in four dump loops out of nine. The five that were not included the ones
that matter most: `dump_stream` feeds the `Store` watch-cache, which
`replace_all`s its entire map from a redump, and the nftables dumps are what
`diff()` turns into a **single atomic** apply.

You may now see `Error::DumpInterrupted` from paths that never produced it.
Retry — that is what the error is for, and `Error::is_dump_interrupted()` is the
predicate. The resync stream already retries for you (thirty attempts, 50 ms
apart).

### 5. `MptcpEndpointBuilder::port` installed on the wrong port

**Affects:** MPTCP endpoints with a port.

`MPTCP_PM_ADDR_ATTR_PORT` is host order; nlink wrote **and read** it big-endian,
so it round-tripped through nlink perfectly while the kernel held the swap:

```
$ ip mptcp endpoint show    # after nlink installed .port(8080)
10.9.8.1 port 36895 id 1 signal
```

Fixed. Any endpoint installed by an older nlink is on the swapped port — flush
and re-add.

### 6. `diagnostics::LinkRates::total_bps` was 8× low

**Affects:** anything reading `nlink::LinkRates`.

The fields were named `rx_bps`/`tx_bps` while being documented and computed as
**bytes** per second, and `total_bps()` summed them and called the result bits.
A "saturated at 1 Gbps" alert did not fire until 8 Gbps.

```rust
// 0.25
rates.rx_bps                 // a *byte* count, despite the name

// 0.26
rates.rx_bytes_per_sec       // the field, honestly named
rates.rx_bps()               // bits — comparable against a link speed
```

Aggravated by the crate having a *second* `LinkRates` (in `netlink::stats`) that
had it right, with only the wrong one re-exported at the crate root. They now
use identical vocabulary.

### 7. `min_bytes_for_rate` gated on a packet count

**Affects:** `DiagnosticsConfig`.

Named and documented in bytes, compared against `rx_packets + tx_packets`. Set
to `1_000_000` meaning "1 MB", you waited for a million packets — roughly 1.5 GB
at MTU. Loss and error detection stayed silent **~1500× longer** than intended.

It compares bytes now, so your existing value fires *much* earlier. If you tuned
it against the old behaviour, divide by about 1500.

### 8. `has_module()` no longer skips your tests

**Affects:** anyone using `nlink::require_module!` / `require_modules!`.

It checked `/sys/module/<name>` alone, documented as covering built-ins. It does
not — sysfs publishes a directory for a built-in only if it exports parameters,
and for a loadable module only once it is loaded. On the box this was measured
on, **179 of the first 200 modules the kernel indexes have no `/sys/module`
entry**.

Every miss became a skip, and a skipped test reports `ok`. Tests of yours that
have been quietly skipping will now **run** — and may fail, on their own merits.

`NLINK_TEST_STRICT_MODULES` takes a comma-separated list of modules the
environment is expected to provide; a skip for any of them becomes a failure.
Worth setting in CI.

### 9. Convenience wrappers could not be called from a small program

`conn.del_netem("eth0").await` did not compile in a downstream crate:

```
error: queries overflow the depth limit!
  = note: query depth increased by 130 when computing layout of
          `{async block@src/main.rs:1:1: 1:15}`
```

The error names *your* async block, never mentions nlink, and no attribute
nlink can set fixes it — `recursion_limit` belongs to the crate that hits it.
It affected `del_netem`, `apply_netem`, `plug_buffer`,
`RateLimiter::{apply,remove}`, `PerHostLimiter::{apply,remove}` and
`PerPeerImpairer::apply`.

Nothing in nlink's own tree saw it, because rustc caches layout queries: a
program that touches nlink anywhere else computes these layouts on a shallow
stack first and hits the cache later. Only a program with nothing else in it
— a small downstream tool — takes the deep path first. The shipped
`route_tc_netem` example calls two of the three affected netem methods and
builds clean.

One `Box::pin` on the dump path fixes all of it, and every wrapper written
from here inherits it. Nothing to change on your side: code that did not
compile now does (#310, #315).

## Compile errors you may hit

These break the build rather than the behaviour, which is the better kind.

| change | why |
|---|---|
| `TcHandle::CLSACT` is now `0xFFFF_FFF1` | `pkt_sched.h` defines `TC_H_CLSACT` as an alias of `TC_H_INGRESS`. `0xFFFF_FFF2` is `TC_H_MAKE(TC_H_CLSACT, TC_H_MIN_INGRESS)` — a *filter* parent. Use `TcHandle::CLSACT_INGRESS` / `CLSACT_EGRESS` for filters. |
| `MptcpEndpointBuilder::dev` / `MptcpSubflowBuilder::dev` **removed** | Documented as resolving to an ifindex; resolved nothing, so endpoints reached the kernel with no interface binding. Resolve through a `Connection<Route>` in the right netns and pass `.ifindex(n)`. |
| `diagnostics::LinkRates::{rx_bps, tx_bps}` are methods now | See section 6. |
| the `tuntap-async` feature is **removed** | It gated zero lines: no `#[cfg(feature = "tuntap-async")]` anywhere, no `create_async` symbol. `--features tuntap-async` now fails instead of silently doing nothing. |
| `FlowerFilter::write_options` can return `Err` | See section 2. |
| `Batch::len()` / `is_empty()` count submissions | An op that failed to encode used to be dropped, misaligning `BatchResults` against your submission order. |

## Newly nameable, newly callable

Types that appeared in public signatures while living in private modules — so a
downstream crate could see them and not name them:

- **`ValidationErrorInfo`** — `Error::validation` takes
  `impl IntoIterator<Item = ValidationErrorInfo>`, so **the public constructor
  was uncallable**.
- **`config::{ApplyError, LinkChanges}`** — `ApplyResult` is `Serialize` under
  `serde`, so `ApplyError` was in the JSON ABI while unnameable in Rust.
- **`tuntap::{TunTapInfo, list_devices}`** — the feature's only enumeration API.
- **`output::{JsonBuilder, format_number, format_rate}`**.
- **`route::RouteType`, `neigh::NeighborState`** — argument types of
  `Ipv4Route::route_type` and `Neighbor::state`, reachable only through
  `netlink::types::` or, for the latter, under the renamed `neigh::State`.
  Every doc example in those two modules imported them from the module
  itself, which is now the path that works (#316).

## New

- **`Connection::<Ethtool>::get_string_set`** — statistic names, private-flag
  names, feature names, link-mode names. Every piece existed except the request.
- **`plug_buffer` / `plug_release_one` / `plug_release_indefinite` /
  `plug_set_limit`** — the plug qdisc starts buffering the moment it is
  installed, and there was no way to release. The doc example called two of
  these; neither existed.
- **`RecvSession::recv_with_timeout`** — CLAUDE.md's canonical recv-loop
  template has always named it, with zero occurrences crate-wide.
- **`OvpnPeer::local_socket()`**, mirroring `remote_socket()`.

## Behaviour that is simply better now

You do not need to do anything about these.

- **Timeouts are per-frame.** The 30s default used to wrap a whole dump, so a
  conntrack table with millions of entries failed while the kernel was streaming
  perfectly well. Streaming dumps had **no** timeout at all and hung forever on
  a stalled kernel. Both are inactivity deadlines now.
- **`ext_ack` actually arrives.** The TLV offset assumed a capped ACK and nlink
  never set `NETLINK_CAP_ACK`, so every kernel rejection reached you as a bare
  errno while the kernel was sending a sentence. `errno = 22` now comes with
  `"Netlink action attributes missing"` or whatever the kernel said.
- **`reconcile()` converges.** It could not bootstrap (the kernel's implicit
  root qdisc tripped a guard), could not notice an edited rule (the comparison
  looked only at kind and classid, both derived from the rule's index), could
  not survive a changed rule count, and could not run twice without reporting
  changes (the fq_codel target was compared against a codel-quantised readback:
  20 ms in, 19999 µs back).
- **Class and filter dumps return things.** They asked for ifindex 0, which the
  kernel answers with an empty, *successful* dump — so `get_classes` and
  `get_filters` were always empty, and `dump_live_tree` therefore believed
  nothing was installed.
- **`RateLimiter::ingress` installs.** It was missing `NLM_F_CREATE` and sending
  a 28-byte `tc_u32_sel` where the struct is 32.
- **Declared MACs and MTUs are applied.** A declared MAC was compared by
  nothing, so `.address(mac)` on an existing interface produced an empty diff
  forever; VXLAN, macvlan and IFB dropped a declared MTU on create.
- **`ethtool advertise()` emits something.** It collected modes into a `Vec`
  with no read site while a comment said to wire it up "when a downstream user
  asks for it" — the setter had already shipped.
- **Event streams stop hot-spinning** on a dead fd, and `fail_all` no longer
  leaves multicast subscribers parked forever.
- **`spawn_*_with_etc` cannot leave the child with no `/sys`.**

## Wire constants

Roughly 50 attribute ids and enum discriminants were re-transcribed from the
kernel headers — MACsec (where `GcmAes256` was configuring **AES-128**), bridge
`IFLA_BRPORT_MCAST_FLOOD`, nl80211, devlink, netkit, nft log, ETS, flower CT,
nexthop buckets, srv6. Five encoders wrote kernel-native fields in the wrong
byte order.

You cannot have depended on these — a wrong attribute id means the kernel acted
on something else, silently. They are listed in the CHANGELOG.

The audit gates that missed them are widened: `audit-uapi-constants` reads plain
`pub const`s as well as `#[repr]` enums (1764 constants checked, up from 642
discriminants), `audit-bytes-le` bans writers as well as readers, and
`audit-dump-termination` is new.

## Documentation now compiles

508 doc examples were ```` ```ignore ```` — rendered, never compiled. **24 of
them did not build**, which is what three years of `ignore` buys: `add_qdisc`
called with three arguments, `"100mbit"` where `Rate` is required,
`QfqConfig::new().handle(…)` on a config that has no setters,
`use rip_tuntap::{TunTap, Mode};` (the crate's name three renames ago), and
`events()` called synchronously five releases after it went async.

They are ```` ```no_run ```` now, and `scripts/audit-doc-examples.sh` fails
the build on a new ```` ```ignore ````. `text` remains for a block that is
not Rust.

The recipes under `docs/recipes/` had never been compiled either — 91 Rust
blocks, checked only by a grep for known-stale shapes. **37 did not build**
(#319). `src/recipe_doctests.rs` pulls each recipe in with
`#[doc = include_str!]` under `#[cfg(doctest)]`, so rustdoc compiles them all
now, and the grep is deleted: every pattern it looked for is a compile error.

**Five of the failures were not documentation bugs at all.** The examples
were describing a library that could not do what they said, and each is
fixed in this release:

| | |
|---|---|
| #310, #315 | methods that overflowed rustc's recursion limit in any caller |
| #313 | `MatchallFilter` could not carry actions |
| #316 | `RouteType` / `NeighborState` unnameable from their own modules |
| #317 | `destroy_matching` took a filter nothing could build |

`bidirectional-rate-limit.md` is the clearest of them: it called
`MatchallFilter::actions(…)`, which did not exist until #313 was fixed. The
recipe had been describing the API the library should have had, and nothing
compiled it, so nobody found out.
