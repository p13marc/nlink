# Upgrading from 0.29.0 to 0.30.0

0.30.0 is an nftables release. It reshapes the public nftables types once, so
that sets, maps, timeouts and the other `nft` features this cycle adds — and
whatever comes after — can grow without another major bump. It also fixes the
declarative layer in places where a rule or set never converged.

Read the compile breaks first; they are mechanical. Then read the behaviour
changes: several declared rules are replaced **once** on the first apply after
upgrading, because what nlink writes for them changed.

---

## ⚠️ Compile breaks

### 1. Growing `Expr` variants carry payload structs

**Affects:** code that builds `Expr::Lookup`, `Expr::Limit`, `Expr::Log`,
`Expr::Masquerade` or `Expr::Redirect` directly, or matches on their fields.

These five now wrap a `#[non_exhaustive]` struct — the shape `Expr::Nat(NatExpr)`
already had — so a field added later is not a break. Build them with `new()`
and setters, and push them with `Rule::expr` (or `.into()`):

```rust
// 0.29.0
Expr::Lookup { set: "s".into(), sreg: Register::R0 }
Expr::Limit { rate: 10, unit: LimitUnit::Second, burst: 5 }
Expr::Log { prefix: Some("x".into()), group: None }
Expr::Masquerade
Expr::Redirect { port: Some(3128) }

// 0.30.0
LookupExpr::new("s", Register::R0).into()            // .invert(), .dreg(r) are new
LimitExpr::packets(10, LimitUnit::Second).into()     // .burst(n), .over() are new
LogExpr::new().prefix("x").into()                    // .group(g)
MasqExpr::new().into()
RedirExpr::new().port(3128).into()
```

`Expr::FlowOffload`'s field is renamed `table` → `flowtable`: it always held
the flowtable's name. `NatExpr` is now `#[non_exhaustive]`; build it with
`NatExpr::snat`/`dnat` and its setters, as before.

The `Rule` helpers (`limit`, `log`, `masquerade`, `redirect`,
`match_*_in_set`, …) are unchanged.

### 2. Decoded `RuleExpr` variants are `#[non_exhaustive]`

**Affects:** code that builds a `RuleExpr` literal (usually a test comparing
`rule.expressions()` against one) or matches a variant without `..`.

Match with `..`, which keeps compiling as variants gain fields:

```rust
// 0.29.0
assert!(exprs.contains(&RuleExpr::MetaSet { key: MetaKey::Mark, sreg: Register::R0 }));

// 0.30.0
assert!(exprs.iter().any(|e| matches!(
    e,
    RuleExpr::MetaSet { key: MetaKey::Mark, sreg: Register::R0, .. }
)));
```

`RuleExpr::Lookup` gained `dreg` and `invert`: inverted (`!= @set`) and map
lookups now decode typed instead of as `Unknown`.

### 3. `SetElement` has private fields; element calls take the `Set`

**Affects:** `elem.key` field access, `SetElement { key }` literals, and every
`add_set_elements` / `del_set_elements` call (on `Connection` and
`Transaction`).

```rust
// 0.29.0
conn.add_set_elements("filter", "blocklist", Family::Inet, &elems).await?;
let bytes = &elem.key;

// 0.30.0 — pass the Set; read the key through its accessor
let blocklist = Set::new("filter", "blocklist").family(Family::Inet).key_type(SetKeyType::Ipv4Addr);
conn.add_set(blocklist.clone()).await?;
conn.add_set_elements(&blocklist, &elems).await?;
let bytes = elem.key();
```

How an element goes on the wire depends on the set's key type and flags, so
the calls need the set itself. An element that does not fit (a 2-byte port
into an IPv4 set) is now an error before anything is sent; on a `Transaction`
it is reported by `commit()`. Elements of interval sets and maps are refused
until those encodings land, rather than written as plain keys.

New constructors: `SetElement::{mark, ifindex, inet_proto, ether}`.

### 4. Set flags are a `SetFlags` newtype

**Affects:** `Set::flags`, `DeclaredSetBuilder::flags`, `DeclaredSet::flags`
and `SetInfo::flags`, which took or held a `u32`.

```rust
// 0.29.0
Set::new("t", "s").flags(NFT_SET_CONSTANT | NFT_SET_INTERVAL)

// 0.30.0
Set::new("t", "s").flags(SetFlags::CONSTANT | SetFlags::INTERVAL)
```

`SetFlags(pub u32)` follows `CtState` and `TcpFlags`; `.bits()` gives the raw
value. The `NFT_SET_*` constants remain.

### 5. `SetInfo`, `Table` and `Flowtable` are `#[non_exhaustive]`

**Affects:** struct literals of these types. They come from dumps
(`list_sets`, `list_tables`, `list_flowtables`); build a `Flowtable` with
`Flowtable::new` and its setters. `SetInfo` also gained `size`.

### 6. `RuleInfo::comment` is now `key` and `comment_text`

`comment` held nlink's declarative identity, the `<key>` of an `nlink:<key>`
comment. It is split in two:

- `key: Option<String>` — that identity, as before;
- `comment_text: Option<String>` — the comment exactly as `nft list ruleset`
  shows it, whoever set it.

Replace `rule.comment` with `rule.key`.

### 7. `NftablesDiff` collections

**Affects:** code that reads the diff's fields directly.

| 0.29.0 | 0.30.0 |
|---|---|
| `rules_to_add: Vec<DeclaredRule>` | `Vec<RuleAdd>` — `.rule`, `.placement` |
| `sets_to_resize` | `sets_to_update` |
| `set_elements_to_add/remove: Vec<(table, family, set, elements)>` | `Vec<SetElementsChange>` — `.set` (a `Set`), `.elements` |

## Behaviour changes

### Declared rules that are replaced once after upgrading

Each of these rules is written differently from 0.29.0, so the first apply
after upgrading reports it changed and replaces it in place. After that it
converges.

- **Set lookups** (`match_saddr_in_set`, `match_daddr_in_set`) now carry the
  `meta nfproto ipv4` guard. Without it, in an `inet` chain an IPv6 packet had
  bytes of its own address looked up as an IPv4 address (#376).
- **Lookups, `limit`, `log` and `reject with tcp reset`** now send exactly
  what the kernel echoes. Before, these never converged at all: they were
  replaced on **every** apply (#374).

### Rules that could not be installed now can

`Expr::FlowOffload` / `Rule::flow_offload` named the flowtable with the wrong
attribute, so every such rule failed with `EINVAL` (#375).

### Typed decodes replace `Unknown`

`rule.expressions()` now decodes `meta`-set, `exthdr`, `ct`, `rt`,
`byteorder`, `bitwise` and `lookup` (plain, inverted and map) as typed
variants. Code matching `RuleExpr::Unknown { name: "lookup", .. }` and the
like stops matching for these. So do expressions using a 32-bit register
(`NFT_REG32_*`, e.g. the loads of a concatenation), now that `Register`
names them: `Register::Reg32_00..=Reg32_15`.

### Declared rule order is enforced

`apply` now puts each chain in declared order — first match wins, so this is
policy. A rule declared between two installed rules is inserted there; rules
found out of order are moved, as few as possible. If you relied on rules
staying wherever they happened to be installed, set
`NftDiffOptions::enforce_rule_order(false)`.

### Rules without a key converge, and their identity changed

A rule declared with `rule()` (no key) used to be added again on every apply.
It now gets a derived key (`~` + a hash of its chain, body and comment), so
the first apply after upgrading adds it once more next to the copies earlier
applies left — those copies have no key, so nlink treats them as foreign and
leaves them. Mark the chain `.exclusive()` to have them removed, or delete
them by hand.

### `Rule::comment` is written verbatim

`.comment("x")` used to store `nlink:x` and make `x` the rule's declarative
identity. It now stores `x` as a plain comment. In an `NftablesConfig`, give
a rule its identity with `rule_keyed`; a comment there is stored after the
key as `nlink:<key> <comment>`. Keyed rules installed by 0.29.0 whose rule
also had a comment were stored under the comment, so the first apply replaces
them once. A key or comment that does not fit is now an error from `diff`
(`NftablesConfig::validate`) instead of a rule installed without an identity.

### Counters are not reset by re-applying

A declared `.counter()` rule that had seen traffic was replaced — and its
counter zeroed — on every apply. It is now left alone.

### Recreating a set a rule references no longer fails

A declared set whose key type or flags change is recreated; the rules bound
to it are now deleted and re-inserted in place around it, instead of the
apply failing with `EBUSY` (#377).
